# Nexa OS 2.0 — Password authentication

Nexa OS 2.0 adds password authentication to the educational shell.

- `useradd USER PASSWORD` creates accounts; passwords must contain at least eight characters.
- `login USER PASSWORD` verifies credentials before changing the active user.
- `passwd PASSWORD` changes the active account password.
- Passwords are stored as PBKDF2-HMAC-SHA256 digests with per-account 16-byte salts, 120,000 iterations, and salts generated by OpenSSL `RAND_bytes`.
- VFS security metadata format `NEXASEC2` persists salts and password digests; the reader retains compatibility with `NEXASEC1` images, whose accounts have no configured passwords.
- Password comparison accumulates digest differences rather than exiting on the first differing byte.

Build now requires OpenSSL Crypto (`find_package(OpenSSL REQUIRED COMPONENTS Crypto)`).

**Security scope:** this is still an educational host-side shell. Passwords are passed as command-line text and may be visible in terminal history/process input; there is no secure password prompt, account lockout, PAM integration, authenticated/encrypted disk image, or hardware isolation. Use a trusted host and do not reuse real passwords. VFS image metadata should be treated as untrusted.
